# Support

SessionScope is early-stage open-source software. Support is best-effort and
centered on defensive, authorized use.

## Where to Ask

- Use GitHub Issues for bugs, feature requests, documentation gaps, and
  reproducible false-positive or false-negative reports.
- Use private security reporting for suspected vulnerabilities in SessionScope
  itself.
- Do not post credentials, tokens, customer code, exploit payloads, or sensitive
  vulnerability details in public issues.

## What to Include

For bug reports, include:

- SessionScope version or commit SHA
- operating system and installation method
- command run and sanitized output
- minimal sanitized fixture or code shape, when possible
- expected behavior and actual behavior

For detection improvements, include:

- framework and language
- sanitized token, session, cookie, or auth-flow pattern
- expected artifact, lifecycle stage, finding, or confidence behavior
- why the pattern is token lifecycle evidence

## Support Boundaries

SessionScope maintainers will not help with exploit automation, unauthorized
scanning, credential theft, bypass instructions, or attacks against live
systems.
